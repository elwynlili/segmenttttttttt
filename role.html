一、安全角色基本概念

零基础入门：如果您是第一次接触Dynamics 365的安全管理，不用担心！本指南将从基础开始，一步一步教会您如何控制Customer Insights - Journeys的导航栏显示。

什么是安全角色？

在Dynamics 365中，安全角色是控制用户访问权限的核心组件，它由两部分组成：

  • 操作权限：定义用户可以对实体执行的操作（创建、读取、更新、删除等）
  • 数据访问级别：定义用户可以访问的数据范围（用户级、业务单位级、父业务单位级、组织级）

Customer Insights - Journeys的权限控制原理

Customer Insights - Journeys的导航栏显示是基于用户的安全角色权限的。简单来说：

  • 如果用户对Journeys相关实体没有读取权限，系统会自动从导航栏中隐藏Journeys功能
  • 这是一个系统内置的机制，不需要额外配置
  • 通过控制实体的读取权限，您可以精确控制用户看到的功能

关于系统自带角色的重要提醒

关键点：请勿直接修改系统自带的现成角色（如"营销专业人员 - 业务"）。因为这些角色在系统更新时会被重置，您的修改会丢失。正确的做法是创建现有角色的副本，然后对副本进行自定义。

Customer Insights - Journeys的许可证和用户管理

与其他Dynamics 365应用不同，Customer Insights - Journeys使用基于容量的许可，而不是基于用户的（席位）许可：

  • 您可以为每个Customer Insights - Journeys实例添加任意数量的用户，无需额外费用
  • 任何在您的Microsoft 365租户上拥有账户的用户都可以使用Customer Insights - Journeys应用
  • 通过设置安全组来限制访问
  • Customer Insights - Journeys是租户级别的许可证，不需要为用户明确分配席位
用户同步提示：要将使用组织Microsoft Entra ID的用户同步到Customer Insights - Journeys应用，只需向他们提供环境URL。当他们尝试使用环境时，他们的身份会同步到Dynamics 365，Dynamics 365会为他们创建用户并分配Marketer角色。

二、隐藏Journeys功能的详细步骤

步骤 1：创建自定义安全角色
  1. 使用管理员账户登录 Power Platform 管理中心
  2. 在左侧导航栏中选择 "环境"，然后点击您要配置的Dynamics 365环境
  3. 点击页面顶部的 "设置" 菜单
  4. 在 "用户 + 权限" 区域下，选择 "安全角色"
  5. 在安全角色列表中，找到与您目标用户权限最接近的角色（例如 "营销专业人员 - 业务"）
  6. 选中该角色左侧的复选框，然后在工具栏上点击 "更多操作" > "复制角色"
  7. 为新角色起一个易于识别的名字，比如"营销专员（无旅程权限）"
步骤 2：配置角色权限（核心步骤）
  1. 在安全角色列表中，找到并点击您刚刚创建的新角色的名称，以打开其权限设置窗口
  2. 在权限窗口中，重点关注以下两个选项卡：
    • "核心记录"选项卡：取消与客户旅程相关的实体（例如 "客户旅程"）的所有权限（读、写、创建等）
    • "自定义实体"选项卡：Customer Insights - Journeys 创建的许多实体都位于此选项卡下。请仔细检查并取消所有与旅程功能相关的实体权限。
  3. 为了彻底隐藏，您可能需要检查的实体包括但不限于：Customer Journey， Marketing Segment(如果细分管理也需隐藏) 等。将它们的权限从任何级别的访问（如"用户"、"业务部门"、"组织"）都改为"无"
  4. 点击 "保存并关闭" 以保存您的设置
步骤 3：将新角色分配给用户
  1. 在环境的 "设置" > "用户 + 权限" 下，选择 "用户"
  2. 在用户列表中，找到并选择您要分配新角色的用户
  3. 点击顶部的 "管理角色" 按钮
  4. 在弹出的对话框中，勾选您刚才创建的新角色（如"营销专员（无旅程权限）"）
  5. 确保取消勾选任何可能包含Journeys权限的其他安全角色
  6. 点击 "确定" 按钮完成分配
步骤 4：验证配置是否生效
  1. 以目标用户身份登录Dynamics 365系统
  2. 打开 "Customer Insights - Journeys" 应用
  3. 检查导航栏是否不再显示 "Journeys" 功能
  4. 尝试通过直接URL访问Journeys功能，确认是否会收到权限错误
重要提醒：请勿直接修改系统自带的现成角色（如"营销专业人员 - 业务"）。因为这些角色在系统更新时会被重置，您的修改会丢失。正确的做法是创建现有角色的副本，然后对副本进行自定义。

其他隐藏导航栏功能的方法

除了调整安全角色权限，您确实有其他方法来隐藏导航栏中的特定功能（如"Journeys"）。这些方法主要在配置层级上操作，可以实现更直接或界面化的控制。

方法 实施层面 核心机制 优点 注意事项
编辑站点地图 应用导航结构 直接修改应用的导航配置文件（SiteMap） 控制精准，可彻底隐藏项目；与权限控制结合更灵活 属于高级定制，需通过解决方案导入导出；修改影响所有使用者
使用新版应用设计器 特定应用界面 在应用设计器的图形化界面中取消勾选对应导航项 操作相对直观简单，无需编辑XML 主要控制整个导航组的显隐，精细度可能不如SiteMap
功能区自定义 特定实体界面 通过RibbonDiffXml隐藏特定命令按钮 针对实体表单或列表上的具体按钮 通常用于隐藏特定按钮，而非主导航项；实现相对复杂

✏️ 编辑站点地图

站点地图定义了Dynamics 365应用的整个导航结构，包括区域、子区域和链接。通过直接编辑SiteMap，可以移除或隐藏特定的导航项目。这是最彻底的方法之一。

操作思路：

  1. 进入解决方案：在Power Platform管理中心，进入相应环境，通过"解决方案"添加现有应用。
  2. 编辑站点地图：在应用组件中找到"站点地图"并进行编辑。这将打开一个XML编辑器。
  3. 修改XML：在SiteMap的XML结构中，找到代表"Journeys"功能的<Area>或<SubArea>元素。您可以注释掉或直接删除该节点。注释掉的优点是便于日后恢复。
  4. 发布更改：保存并发布自定义项。

优势：可以与安全角色深度集成。例如，可以为某个<SubArea>添加<Privilege>元素，指定只有拥有特定实体（如"客户旅程"实体）权限的用户才能看到此导航。如果用户因权限不足无法看到某个区域内的任何子区域，则该区域也不会显示。

🖥️ 使用新版应用设计器

对于由模型驱动应用提供的导航栏，可以使用新版的应用设计器进行图形化界面调整。

操作思路：

  1. 打开应用设计器：访问Power Apps制作门户，找到对应的应用并点击"编辑"。
  2. 编辑导航栏：在设计器中切换到"导航栏"编辑界面，通常在右侧会显示导航结构。
  3. 隐藏项目：找到代表"Journeys"的导航项，取消其勾选状态即可将其隐藏。

这种方法更适合快速隐藏整个导航组，比如"营销"区域下的"客户旅程"子项。

⚙️ 功能区自定义

此方法用于隐藏特定实体表单或列表上的按钮或选项卡，而非主导航栏。技术上是使用<HideCustomAction>元素在功能区定义中移除特定按钮。不过，Microsoft建议，如果目标是隐藏与权限相关的按钮，应优先通过调整安全角色权限来实现，这更符合系统设计。

💡 操作建议

选择哪种方法取决于您的具体需求：

  • 追求精细控制且熟悉高级定制：建议使用编辑站点地图的方法。它功能最强，能与权限系统完美结合，实现基于角色的导航项显示。
  • 需要快速隐藏整个导航组且改动最小：可以尝试新版应用设计器的图形化操作。
  • 核心目标就是权限管控：您最初采用的调整安全角色权限依然是最基本、最推荐的方式。站点地图中的导航选项会根据用户安全角色权限进行评估，无权限的用户将看不到相应导航。

进行任何定制前，请务必在测试环境中充分验证，并做好更改备份。

三、权限级别说明

权限级别的设置位置

操作前准备：在设置权限级别之前，请确保您拥有系统管理员或安全角色管理员的权限，这样才能编辑安全角色。
  1. 登录Dynamics 365系统：使用您的管理员账户登录
  2. 打开高级设置：点击右上角的设置图标（齿轮图标），选择"高级设置"
  3. 进入安全角色管理：在高级设置页面，点击顶部导航栏的"设置" > "安全性" > "安全角色"
  4. 选择并编辑角色：在安全角色列表中，选择要编辑的安全角色，点击"编辑"按钮
  5. 找到目标实体：在安全角色编辑页面，选择相应的选项卡（如"业务管理"、"营销"等）
  6. 设置权限级别：找到目标实体，在其对应的权限列中，通过下拉菜单选择权限级别

权限级别详解

权限级别决定了用户可以访问的数据范围，从严格到宽松依次为：

权限级别 显示标签 描述 适用场景 图标表示
None 无 用户对该实体无任何权限 需要完全隐藏的功能，如Journeys功能 🔒
Basic 基本（用户级） 用户只能访问自己创建的记录 个人工作项，如个人联系人、个人任务 👤
Local 本地（业务单位级） 用户可以访问所在业务单位内所有用户创建的记录 部门内协作，如部门级营销活动、部门客户 🏢
Deep 深度（父业务单位级） 用户可以访问所在业务单位及其所有子业务单位的记录 区域管理，如区域营销总监、区域销售经理 🏙️
Global 全局（组织级） 用户可以访问组织内所有记录 系统管理员，全局营销配置，企业高管 🌍
实用技巧：对于隐藏Journeys功能，您需要将相关实体的权限级别设置为None，这样系统会自动从导航栏中隐藏该功能。

六、最佳实践

专家建议：以下最佳实践来自Microsoft官方文档和行业专家经验，遵循这些建议可以确保您的安全配置既有效又易于维护。

安全角色管理最佳实践

最佳实践 详细说明 实施建议 常见错误
使用最小权限原则 只授予用户完成工作所需的最小权限 先分析用户的具体工作职责，然后只授予必要的权限 为所有用户分配过多权限，导致安全风险
创建专用安全角色 为不同的访问需求创建专用的安全角色，而不是修改系统默认角色 基于业务流程和工作职责设计角色，如"内容创建者"、"活动协调员"等 直接修改系统自带角色，导致系统更新后设置丢失
测试配置 在部署到生产环境前，先在测试环境中验证配置 创建测试用户，模拟实际使用场景，验证权限是否正确 未测试就直接部署，导致用户无法正常工作
文档化配置 记录安全角色的配置详情，便于后续管理和审计 使用Excel或其他工具记录每个角色的权限设置和适用场景 无文档记录，导致后续维护困难
定期审查 定期审查安全角色配置，确保权限设置与业务需求保持一致 每季度或半年进行一次权限审查，调整不符合业务需求的设置 长期不审查，导致权限设置过时

操作流程最佳实践

  1. 从现有角色复制：
    • 始终从与目标权限最接近的现有角色复制，而不是从零开始创建
    • 这样可以确保基础权限正确，只需调整特定实体的权限
  2. 命名规范：
    • 使用清晰、描述性的名称命名自定义角色，如"营销专员（无旅程权限）"
    • 包含角色的核心功能和权限范围，便于识别
  3. 批量分配：
    • 对于多个用户需要相同权限的情况，考虑使用团队来批量分配安全角色
    • 这样可以简化管理，当权限需要调整时，只需修改团队的角色分配
  4. 权限验证：
    • 在分配角色后，务必以用户身份登录验证权限是否正确
    • 检查导航栏显示、功能访问和数据可见性
  5. 系统更新后检查：
    • 在系统更新后，检查自定义角色是否需要调整
    • 系统更新可能会影响权限设置，特别是当有新功能或实体添加时

Microsoft官方建议

关于许可证和用户管理

  • 使用基于容量的许可模型，为Customer Insights - Journeys实例添加任意数量的用户
  • 通过设置安全组来限制环境访问，而不是依赖用户许可证
  • 对于没有Dynamics 365许可证的Microsoft 365用户，可以分配免费的Customer Insights - Journeys用户许可证
  • 如果自动用户同步失败，使用$0用户许可证强制同步

七、故障排除

问题解决指南：遇到权限相关问题时，不要着急！本部分提供了常见问题的详细解决方案，帮助您快速排查和解决问题。

权限验证工具与方法

以下是验证权限配置的四种有效方法，按推荐顺序排列：

  1. 方法一：模拟用户访问
    • 以目标用户身份登录系统
    • 尝试访问预期的数据和功能
    • 检查导航栏是否显示正确的功能
    • 优点：最直接，能完全模拟用户体验
  2. 方法二：使用"以其他用户身份登录"功能
    • 使用系统管理员账户登录
    • 导航至"设置" > "安全性" > "用户"
    • 选择目标用户
    • 点击"以其他用户身份登录"
    • 优点：无需知道用户密码，方便管理员快速测试
  3. 方法三：查看用户的安全角色
    • 导航至"设置" > "安全性" > "用户"
    • 打开目标用户记录
    • 查看"管理角色"显示的安全角色列表
    • 优点：快速了解用户的权限分配情况
  4. 方法四：检查团队的成员和角色
    • 导航至"设置" > "安全性" > "团队"
    • 打开目标团队记录
    • 查看"成员"和"管理角色"选项卡
    • 优点：了解团队级别的权限分配，适用于批量用户管理

权限调试最佳实践

  1. 从简单开始：先验证基本权限，再添加复杂配置
  2. 逐步测试：每次更改后立即测试，避免累积多个问题
  3. 记录更改：记录每次权限更改，便于回滚和排查问题
  4. 使用测试环境：在非生产环境中测试所有权限更改
  5. 参考文档：遇到复杂问题时，参考Microsoft官方文档

八、总结

通过本文档的指导，您可以成功通过安全角色管理控制Customer Insights - Journeys导航栏的显示。核心步骤包括：

  1. 创建一个从现有角色复制的自定义安全角色
  2. 在新角色中移除与Journeys相关实体的所有权限
  3. 将新角色分配给目标用户
  4. 验证配置是否生效

遵循本文档的最佳实践和故障排除指南，可以确保您的权限配置既安全又高效，为不同用户提供恰到好处的访问权限。

最终目标：通过精细的安全角色管理，确保用户只能看到和访问与其工作职责相关的功能，提高系统的安全性和用户体验。
